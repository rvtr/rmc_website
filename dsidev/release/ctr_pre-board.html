PRE-BOARD

PRE-BOARD runs before the familiar BOARD stage, installing a factory firmware. This specific copy of PRE-BOARD installs v0.17.5 firmware, for the 3DS XL (SPR). PRE-BOARD is a DS rom containing prod 3DS ntrboot image. The FIRM starts at 0x7E00, and the CONT (firmware contents) is at 0x180000. The updater process in the FIRM corresponds to ctr/sources/firmware/CTR-Kernel/updater1st/UpdaterProcess in the ctr.7z source code.

Below is a picture of the test rig. A motherboard would be loaded onto the rig's pogo pins. The pins would lead to the cartridge port and button inputs, and a cartridge slot in the back is wired to the pins. Since the motherboard at this point doesn't have any firmware, all software needs to use ntrboot. This is a special recovery mode baked into the SoC, and it requires no extra hardware like screens or software like an operating system to run.

To start, a factory worker would press the test button. This would turn the motherboard on, and would load the PRE-BOARD software from ntrboot. PRE-BOARD has no output on the screens, and instead relies on the power, WiFi, and test rig LEDs to show the current status.

  • During startup: The motherboard's power LED will light up for 1 to 2 seconds and then turn off
  • During writing: The motherboard's WiFi LED will light up at the same time the power indicator turns off (it will turn off when writing is complete)
  • Debug: The status LEDs on the test rig change their pattern every few seconds

You can tell when writing is finished by the power LED being on, the WiFi LED being off, and all test rig LEDs being on. We have close ups of the test rig's LEDs below:

RF GU & MODULE Test

This is an earlier version of RF Test, instead called "RF GU & MODULE Test". It's hard to tell what this program does exactly, but it was built off of WMtest, and has many of the same features such as measuring and generating noise on wireless channels. The WMtest menu can be opened by holding SELECT on boot. RF Test's main feature is sending and receiving commands through UART. This would be done through an SPI<-->UART GBA cartridge adapter, likely connecting the retail DS to a factory test DS. The retail DS (client) would receive control commands, and the factory DS (host) would transmit those commands. A menu to assemble commands can be opened by holding START on boot, the pressing Y.
